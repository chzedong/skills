# 解构开源库 — 生成学习 HTML 文档

帮助前端开发者深度学习开源库：理解项目背景与解决的问题、学习工程化最佳实践、掌握架构设计思路、了解历史关键决策。

## 触发条件

用户消息中包含以下意图之一时触发：
- "分析"/"解构"/"解读"/"学习" + 开源库/项目/仓库
- "帮我理解"/"帮我看看" + 项目名/仓库路径
- "生成"/"写" + 项目文档/学习文档/HTML文档
- 提供本地仓库路径并要求生成解释文档
- "这个库是怎么设计的"/"这个项目的架构"

## 前置依赖

- **Python 3**：命令 `python3` 可用（用于步骤 1 解析 package.json）
- **gh CLI**（可选）：步骤 5 的 GitHub 历史分析需要，未安装则跳过，不影响核心文档生成
- **模板文件**：`skills/deconstruct-oss/template.html`（请在执行时 `read_file` 读取）

## 核心原则

目标用户是前端开发者，文档应帮助他提升：
1. **技术广度** — 了解不同领域的库如何解决问题
2. **架构能力** — 学习优秀的架构设计和模块划分
3. **方案决策能力** — 理解设计 trade-off 和历史决策背景

**输出产物**：一个或多个结构化的 HTML 文件，可本地浏览器打开阅读。

## 操作步骤（概要）

完整操作指南见 companion: `full-guide.md`，请在执行时 `read_file` 读取。

| 步骤 | 阶段 | 概要 |
|------|------|------|
| 0 | 确认输入 | 仓库路径、输出目录、GitHub 地址、分析深度 |
| 1 | 收集基础信息 | README 分析、package.json 工程化识别、目录结构、配置文件 |
| 2 | 核心链路分析 | 入口识别、核心模块追踪、数据流图、代码引用（路径:行号+IDE跳转）、测试用例分析 |
| 3 | 架构设计分析 | 模块划分、设计模式、插件机制、"如果我来写"对比、反模式标注 |
| 4 | 算法与数据结构 | Parser / AST / Diff / 调度算法，含核心思想+复杂度 |
| 5 | GitHub 历史分析（可选） | 关键 commit、高讨论 Issue、Release 路线图 |
| 6 | 规模评估 | 小型→单页面，大型→多页面模块化拆解 |
| 7 | 生成 HTML | 使用 template.html 为基础，含 Mermaid 图、代码高亮、暗色模式。输出到 `chzedong.github.io/` 并自动提交推送 |

## 文档结构（单页面）

```
Header（项目名、简介、徽章、GitHub 链接）
├── 导航目录（固定侧边栏）
├── Section 1: 项目背景
├── Section 1.5: 快速上手 ⭐（示例代码，3-5 行最小示例 + 2-3 个常见场景）
├── Section 2: 工程化方案
├── Section 3: 项目制品
├── Section 4: 项目结构（目录树+依赖图）
├── Section 5: 核心链路（学习路径、数据流图、关键代码、测试用例）
├── Section 6: 架构设计（模块图、设计模式、对比思考、易错点）
├── Section 7: 同类库对比
├── Section 8: 算法与数据结构（如适用）
├── Section 9: 历史演进（可选）
│   └── 关键决策时间线 ⭐（3-5 个关键技术决策 + 原因）
└── Section 10: 学习要点总结
```

## 关键约束

- **输出与部署**：HTML 文件必须生成到 `chzedong.github.io/<库名>/` 目录下。生成完成后自动执行 `git add . && git commit -m "docs: deconstruct <库名>" && git push origin main`（推送前设置代理环境变量）
- **只读操作**：分析过程只读取仓库文件，不修改任何内容
- **快速上手优先**：深度分析前提供 3-5 行最小可运行示例 + 2-3 个常见场景示例
- **图表用 Mermaid**：复杂流程图 / 架构图 / 依赖图 / 时序图使用 `<pre class="mermaid">` 嵌入，每个图下加说明 caption；简单结构用纯文本描述
- **代码引用规范**：每次引用代码必须标注文件路径和行号，格式 `src/core/store.ts:42-68`；核心代码段提供 IDE 跳转链接（`vscode://file/<absolute-path>:行:列`）
- **"如果我来写"对比**：每个核心模块至少一个直觉做法 vs 实际做法的对比框
- **关键决策提取**：从 GitHub release/issue 中提取 3-5 个有教学价值的技术决策，标注版本号和原因
- **准确性**：不确定的内容标注"推测"，不要编造
